## Trust Boundaries

| Boundary | Description |
|---|---|
| HTTP client → validation layer | Direct clients can bypass the browser and submit malformed or oversized values. |
| Validation/service → repository | Normalized values cross into parameterized SQLite writes. |
| API → browser origin | CORS headers control which configured development origins may read browser responses. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-01-05 | Tampering | Pydantic/domain validation | high | mitigate | Trim and bound text, enforce year range and ISBN check digits, and reject before repository calls. |
| T-01-06 | Denial of service | JSON/text boundary | medium | mitigate | Apply maximum field sizes and typed scalar parsing before SQLite work. |
| T-01-07 | Information disclosure | Error and health handlers | medium | mitigate | Stable non-sensitive envelopes omit database paths and tracebacks. |
| T-01-08 | Spoofing | CORS middleware | medium | mitigate | Exact origins and tested preflight; explicitly document that CORS is not authorization. |
| T-01-SC | Tampering | Dependency installation | high | mitigate | Plan 01 blocks flagged package installation until official registry legitimacy is verified. |
</table>
